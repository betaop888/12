# Плейстиль Brawl Ball — UP

`default_up.pyla` — переработанный вариант вашего плейстиля для боевой поддержки в Brawl Ball 3v3/5v5. Рассчитан на направление атаки **вверх экрана**; это предположение, а не определение ворот. Совместимость проверена по исходникам [PylaAI](https://github.com/PylaAI/PylaAI) на коммите `763c38926fbb3e2edc074db1c3ca2ddb9350d325`.

## Установка

1. Сделайте резервную копию своего `playstyles/default_up.pyla` в папке PylaAI.
2. Скопируйте новый `default_up.pyla` из этого репозитория в папку `playstyles` PylaAI.
3. В интерфейсе PylaAI выберите плейстиль **Brawl Ball - UP (combat support)**; при необходимости перезапустите программу. Запускайте матч, где атакующая сторона находится сверху экрана.

## Что изменено

- При отсутствии противников бот продвигается вверх; при встрече учитывает дистанцию бойца и дальность атаки, отходит от слишком близкой угрозы или сближается с дальней. Бойцы с нулевой безопасной дистанцией играют агрессивнее; на комфортной дистанции используется боковое движение с приоритетом продвижения.
- Стены и другие препятствия проверяются через API PylaAI. При преграде перебираются направления с кратковременным сохранением стороны обхода; если все направления заблокированы, выдаётся остановка вместо намеренного движения в стену. Сам PylaAI может дополнительно включить свой механизм выхода из застревания.
- Ближайший обнаруженный объект используется для проверки дальности и видимости автоатаки. Настоящие противники отдельно учитываются для дистанции, а способности не тратятся на призванные объекты. Небольшое раздвижение с союзниками уменьшает скученность.
- Удерживаемая атака начинается только при доступной цели и отпускается по времени зарядки или при потере возможности атаковать; повторное нажатие в том же кадре исключено.
- Уронные суперы используются только по видимому противнику в радиусе супера, гаджет — при близком противнике; есть небольшие защитные интервалы между попытками. Суперы других типов намеренно сохраняются, поскольку их автоматическое применение может быть неуместным.

## Важные ограничения

В проверенной версии PylaAI плейстиль получает позиции персонажей, призванных объектов и препятствий, но **не получает мяч, владение мячом, ворота, счёт, здоровье, патроны или направление атаки**. Плейстиль не может прицельно управлять ударом или пасом: `attack()` и `use_super()` лишь нажимают кнопки, а цель выбирает игра. Проверка ближайшего объекта — только приближение к поведению автонаведения, а не гарантия выбранной игрой цели.

Поэтому этот файл **не умеет намеренно искать мяч, защищать свои ворота, распознавать владение, пасовать или прицельно забивать**. С мячом автоматическое нажатие атаки или супера может привести к нежелательному удару. Для полноценной стратегии Brawl Ball потребуются изменения самого PylaAI: детектор мяча и ворот, определение владения и API управления направлением удара. Навигация здесь локальная: она не строит полную карту и не гарантирует проход сложных лабиринтов. Разные модели, задержки и особенности отдельных бойцов влияют на результат.

## Проверка

Автономные тесты, без установки зависимостей:

```sh
python -m unittest discover -s tests -v
```

Для дополнительной проверки на реальном интерпретаторе и данных конкретной версии PylaAI (Linux/macOS):

```sh
PYLA_SOURCE=/путь/к/PylaAI python -m unittest discover -s tests -v
```

В PowerShell: `$env:PYLA_SOURCE = 'C:\путь\к\PylaAI'; python -m unittest discover -s tests -v`. Тесты моделируют входные данные и действия; они **не заменяют матч на устройстве**. Реальная игра и качество распознавания в этом окружении не проверялись.
