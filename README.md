# Плейстиль Brawl Ball — UP

`default_up.pyla` — переработанный вариант вашего плейстиля для боевой поддержки в Brawl Ball 3v3/5v5. Рассчитан на направление атаки **вверх экрана**; это предположение, а не определение ворот. Совместимость проверена по исходникам [PylaAI](https://github.com/PylaAI/PylaAI) на коммите `763c38926fbb3e2edc074db1c3ca2ddb9350d325`.

## Установка

1. Сделайте резервную копию своего `playstyles/default_up.pyla` в папке PylaAI.
2. Скопируйте новый `default_up.pyla` из этого репозитория в папку `playstyles` PylaAI.
3. В интерфейсе PylaAI выберите плейстиль **Brawl Ball - UP (combat support)**; при необходимости перезапустите программу. Запускайте матч, где атакующая сторона находится сверху экрана.

## Исправление движения после возрождения

Плейстиль и раньше пытался идти вверх без союзников и противников. Однако PylaAI может считать джойстик всё ещё нажатым после смерти, когда игра уже отменила касание; при неизменном направлении повторная команда не всегда восстанавливает движение. Это возможная причина наблюдаемого поведения, а не установленный по записи факт.

Для исправления в исходной Python-версии PylaAI установите **все три части**:

1. Скопируйте `default_up.pyla` в `playstyles` PylaAI.
2. Сохраните копии своих конфигов и перенесите `bot_config.toml` и `debug_settings.toml` в папку `cfg`. В них изменены только задержка движения и повторная отправка джойстика. Если у вас есть другие личные настройки в этих файлах, вместо замены измените только `minimum_movement_delay = 0.0` в `bot_config.toml` и `re_apply_movement = true` в `debug_settings.toml`.
3. Сохраните копию `play.py` в PylaAI и примените `patches/pylaai-respawn-recovery.patch` **в папке PylaAI**, затем перезапустите программу. Сначала проверьте совместимость патча, указав свой полный путь к файлу:

```sh
git apply --check /путь/к/12/patches/pylaai-respawn-recovery.patch
git apply /путь/к/12/patches/pylaai-respawn-recovery.patch
```

В PowerShell, например: `git apply --check "C:\путь\к\12\patches\pylaai-respawn-recovery.patch"`, затем `git apply` с тем же путём. Требуется Git. Если проверка не прошла, не применяйте патч принудительно: возможно, версия исходников отличается. Патч рассчитан на коммит PylaAI, указанный выше. Изменение `play.py` **не патчит скомпилированный `.exe`**; для него доступны только изменения плейстиля и конфигов.

Патч отпускает управление при потере игрока и повторно нажимает джойстик после его обнаружения. Пока игрок обнаружен, но рядом не видно персонажей, касание дополнительно переинициализируется раз в две секунды: это может давать короткую паузу в движении. Штатный механизм антизастревания при этом не сбрасывается. Плейстиль дополнительно проверяет короткий безопасный путь, если обычная проверка препятствий блокирует все направления и вокруг нет персонажей.

Если после установки персонаж всё равно не двигается, возможно, детектор не видит самого игрока: в этом случае движок не вызывает плейстиль и исправление не может заставить его безопасно двигаться. Включите `match_logging = true` в `cfg/debug_settings.toml`, перезапустите программу и приложите запись экрана и лог матча из `match_logs/default/` (перед отправкой проверьте его содержимое).

## Что изменено

- При отсутствии противников бот продвигается вверх; при встрече учитывает дистанцию бойца и дальность атаки, отходит от слишком близкой угрозы или сближается с дальней. Бойцы с нулевой безопасной дистанцией играют агрессивнее; на комфортной дистанции используется боковое движение с приоритетом продвижения.
- Стены и другие препятствия проверяются через API PylaAI. При преграде перебираются направления с кратковременным сохранением стороны обхода; если все направления заблокированы, при отсутствии персонажей дополнительно проверяется короткий путь; если и он заблокирован, выдаётся остановка вместо намеренного движения в стену. Сам PylaAI может дополнительно включить свой механизм выхода из застревания.
- Ближайший обнаруженный объект используется для проверки дальности и видимости автоатаки. Настоящие противники отдельно учитываются для дистанции, а способности не тратятся на призванные объекты. Небольшое раздвижение с союзниками уменьшает скученность.
- Удерживаемая атака начинается только при доступной цели и отпускается по времени зарядки или при потере возможности атаковать; повторное нажатие в том же кадре исключено.
- Уронные суперы используются только по видимому противнику в радиусе супера, гаджет — при близком противнике; есть небольшие защитные интервалы между попытками. Суперы других типов намеренно сохраняются, поскольку их автоматическое применение может быть неуместным.

## Важные ограничения

В проверенной версии PylaAI плейстиль получает позиции персонажей, призванных объектов и препятствий, но **не получает мяч, владение мячом, ворота, счёт, здоровье, патроны или направление атаки**. Плейстиль не может прицельно управлять ударом или пасом: `attack()` и `use_super()` лишь нажимают кнопки, а цель выбирает игра. Проверка ближайшего объекта — только приближение к поведению автонаведения, а не гарантия выбранной игрой цели.

Поэтому этот файл **не умеет намеренно искать мяч, защищать свои ворота, распознавать владение, пасовать или прицельно забивать**. С мячом автоматическое нажатие атаки или супера может привести к нежелательному удару. Для полноценной стратегии Brawl Ball потребуются изменения самого PylaAI: детектор мяча и ворот, определение владения и API управления направлением удара. Навигация здесь локальная: она не строит полную карту и не гарантирует проход сложных лабиринтов. Разные модели, задержки и особенности отдельных бойцов влияют на результат.

## Проверка

Автономные тесты, без установки зависимостей:

```sh
python -m unittest discover -s tests -v
```

Для дополнительной проверки на реальном интерпретаторе и данных конкретной версии PylaAI (Linux/macOS):

```sh
PYLA_SOURCE=/путь/к/PylaAI python -m unittest discover -s tests -v
```

В PowerShell: `$env:PYLA_SOURCE = 'C:\путь\к\PylaAI'; python -m unittest discover -s tests -v`. С `PYLA_SOURCE` также проверяются применение патча и цикл пропажи/возвращения игрока на методах `Play.main`, `Play.loop` и `WindowController.move` с моделируемыми касаниями. Тесты **не заменяют матч на устройстве**. Реальная игра и качество распознавания в этом окружении не проверялись.
